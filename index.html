    Tecnologias: Vue.js, TypeScript, Java 11, Spring Boot, Maven, JPAQuery, PostgreSQL, OracleDB, MongoDB, Docker, CI/CD, Grafana

    O caso completo
    Problema
    A tabela da frota tem dezenas de colunas, e cada setor precisa de um recorte diferente para prestação de contas. O relatório era fixo: saía sempre igual, independente do que o usuário estivesse vendo na tela.
    Decisão
    Tornei as colunas dinâmicas e fiz o filtro ativo seguir junto para a exportação. O que está na tela é o que cai no PDF ou na planilha.
    Resultado
    Cada setor tira o próprio recorte sem pedir um relatório novo para o time.

    Conexa Saúde

    Desenvolvedor Front-end, remoto. Plataforma de telemedicina.

    • Modularização do prontuário eletrônico e migração de JSP para React.
    • Migrei módulos do prontuário de JSP legado para React com Hooks e TypeScript, sem tirar do ar o que já funcionava.
    • Transformei os formulários em módulos configuráveis: cada clínica cria os campos de que precisa, sem deploy.
    • Mantive os módulos de regras de negócio em Vue.js, num time Scrum.

    Tecnologias: React, Vue.js, TypeScript, JavaScript, JSP

    O caso completo
    Problema
    O prontuário rodava em JSP legado, e cada clínica precisava de campos diferentes. Cada campo novo virava chamado, deploy e espera. O time de produto era gargalo de uma coisa que, no fundo, era configuração.
    Decisão
    Migrei os módulos para React aos poucos, convivendo com o JSP, e modularizei os formulários para que o campo virasse dado, não código.
    Resultado
    A própria clínica cria os campos de que precisa, sem deploy no meio.

    Experimente: crie um campo no prontuário

    Prontuário da clínica

    Dados de exemplo. No sistema real, o campo vira configuração da clínica, e nenhum deploy acontece.
